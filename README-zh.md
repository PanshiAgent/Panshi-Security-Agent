# Panshi(磐石) Security Agent 在 CyberGym 上的测试报告

- **Agent**: Panshi（磐石）Security Agent
- **Model**: DeepSeek-V4-Pro-0813 (deepseek-v4-pro)
- **Benchmark**: CyberGym Level 1
- **Success Rate**: 95.4% (final-submission metric)
- **Category**: agent
- **Language**: [English](README.md) | 中文

Panshi(磐石) Security Agent 是一款面向真实世界漏洞挖掘的自研代理系统，以证据与资产双图谱为核心驱动。

## 1. 摘要

我们在 CyberGym（Wang et al., ICLR 2026）基准上对 Panshi(磐石) Security Agent 进行评估。该基准由 1,507 个真实世界漏洞复现任务构成，任务源自 OSS-Fuzz 与 ARVO，横跨 188 个开源项目。CyberGym 要求 AI Agent 基于 pre-patch 任务材料复现一个已被描述的真实漏洞，生成一个最终输入——该输入须在 vulnerable 构建上触发崩溃，同时在隐藏的 patched 构建上保持干净。

Panshi 是一款证据驱动、面向真实世界漏洞挖掘的自研 AI Agent，底座模型为 **DeepSeek-V4-Pro-0813**。系统共解决 **1438/1,507** 个任务，final-submission 指标下整体通过率 **95.4%**，全部由服务器端隐藏差分执行验证。所有任务均在网络隔离容器中完成，采用 pass@1 单次尝试，agent 全程不接触 patched 构建。

## 2. Agent 设计

### 2.1 设计原则

Panshi 的核心是**证据驱动**：所有诊断信号——源码读取、shell 输出、调试器断点命中、sanitizer 诊断——都是**证据**，但任何单一证据都不构成解；任务仅当提交的输入通过 vulnerable 触发与 fixed-clean 的差分验证后才关闭。围绕一个**共享事实层（shared fact layer）**组织多路探针，各探针独立持有假设、并行推进，产出的观察汇入事实层，由事实层决定哪些假设被支持、哪些被否证。以下四条原则贯穿系统设计。

**（1）双图谱驱动与多路假设并行。** 相比真实世界的漏洞挖掘，CyberGym 基准是一个相对受限、具有确定性解的有限状态搜索空间。Panshi 以两类结构化知识为驱动：已发现的确定性事实（证据）与已确认的可达路径，二者分别沉淀为事实图谱与资产（可达性）图谱。主 agent 负责推演攻击方向、下发假设，把宽泛的代码探索拆解为一系列可证伪的子问题；多个子 agent 各携带一个具体假设（疑似 sink、输入载体、触发机制等）独立向前推进。任何观察均作为证据汇入共享事实层，后续决策基于事实层而非任一探针的私有状态，避免单线推理陷入局部最优。到达某个代码位置只是可达性证据，唯有提交验证通过才构成解；失败探针的证伪证据同样留存于事实层，供其它探针避坑、收敛攻击方向，最终得到一条可达任务目标的攻击路径。

**（2）长过程的可靠性。** 部分漏洞复现是长程调查，单线推理易在数十步后陷入死胡同或丢失早期线索。Panshi 在持久的决策状态上工作：每回合将计划、待解问题、任务列表与证据重建进决策上下文，并对每一步工具产出给出确定性摘要，使上下文压力、重试与工具输出对决策层可见、可回溯，且不因压缩丢失对后续实验重要的因果关系。当静态证据不足以判定当前方向时，系统保留不确定性并转向动态验证，而非假设路径不可达；纠偏机制周期性复盘已积累事实、及时终止死胡同并重定向，让长时调查在最后一步仍与初始目标连贯。

**（3）面向小上下文的本地记忆。** 本次测试在 128K 上下文窗口下进行。Panshi 将工作区与轨迹落地于本地文件系统：大段源码、工具原始输出与中间构造不长期驻留上下文，而是按需读取、用后摘要，使有限上下文始终保留决策所需的高密度信息，而非被静态文本占满。决策状态持久化于本地，可在上下文压力下被重建，而不依赖对话历史的完整保留。系统另设一个执行审计层，以结构化图谱视角监督各探针的执行流程，其研判结论沉淀于本地、仅以紧凑形式回传决策层，使全局进度把控不挤占有限的上下文窗口。

**（4）基于可观测事实验证。** Panshi 不停留在静态推理上，而是构建执行环境、运行触发输入，以可观测的动态行为——如崩溃位置、类型与访问方向——判定是否命中目标漏洞。任何无法由执行证据支撑的结论均视为幻觉或误报而不被接受；每次构造只改变一个变量并记录结果，使失败的尝试对下一决策有用，而非沦为无解释的突变。在 CyberGym 要求"vul 崩且 fix 不崩"的严格判据下，最终提交的 PoC 必须被证据证成、而非被推理假设出。

### 2.2 工具面

Panshi 使用标准工具面（源码检视、工作区与执行、动态诊断、submit_poc），不引入任何任务专属的特殊工具。工具可用性按任务阶段动态控制。没有特定于任务的标识符、历史 PoC、补丁、项目解决方案或数据集目标知识。

## 3. 实验设置

本评估严格遵循 CyberGym 官方关于代理支架、动态执行、网络访问及验证机制的 [FAQ 披露指南](https://github.com/sunblaze-ucb/cybergym/blob/main/FAQ.md)。

### 3.1 基准

CyberGym（Wang et al., 2026）共含 1,507 个任务，数据源自 OSS-Fuzz（Google 持续 fuzzing 服务）与 ARVO 数据集（Mei et al., 2024），覆盖 188 个开源项目。每项任务提供漏洞的文字描述（涉及大致位置、类型、根因）与 pre-patch 源码。agent 需产出一个 PoC 输入，使其在 pre-patch 二进制上触发 sanitizer 崩溃；服务器端进一步验证该 PoC 在 post-patch 二进制上不再崩溃（差分执行），以确认命中的是该具体漏洞而非既有缺陷。post-patch 二进制仅用于服务器端判分，对 agent 不可见。本次评估在 Level 1 进行。

### 3.2 Agent 配置

| 项目              | 设置                                                     |
| ----------------- | -------------------------------------------------------- |
| Benchmark         | CyberGym Level 1（1,507 个 ARVO 与 OSS-Fuzz 任务）       |
| 模型              | DeepSeek-V4-Pro-0813                                     |
| 单任务时限        | 4 小时（14,400 秒）                                      |
| 预注入（preseed） | 无；每个任务从零开始                                     |
| 动态环境          | CyberGym 官方任务级 vulnerable 镜像；无 patched 镜像访问 |
| 网络              | 域名白名单，仅限模型服务 + 本地 CyberGym 提交服务        |
| 已修补版本访问    | 无                                                       |
| 重复              | 每任务一次有效运行；仅基础设施故障重跑                   |

### 3.3 输入与信息隔离

- **Level 1 输入：** 每项任务仅提供漏洞描述与预补丁源代码，以及任务相关的 harness、二进制和语料。每个任务拥有独立容器、工作目录与任务状态；容器不挂载其它任务的数据、实验数据库、提交逻辑或 Docker 控制接口。任务标识符与服务器端提交元数据保留在 agent 工作区之外，对话与任务记忆同样相互隔离。
- **泄漏源移除：** 动态执行环境启动后，仅以只读方式挂载存在漏洞的二进制文件，而非完整 vulnerable 镜像。镜像交付 agent 前，按 CyberGym 文档要求删除 `/src/**/.git`（Git 历史）与 `/tmp/poc`（参考 PoC）等可揭示预期答案的材料。由此，vulnerable 镜像内部原有的泄漏源均不会出现在 agent 运行环境中。
- **patched 隔离：** agent 不接收 patched 仓库/镜像、patch diff、参考 PoC、评测数据库、`fix_exit_code` 或差分判定，亦无法访问验证器地址、服务器端凭据或修补版本。任务之间不存在任何轨迹、PoC 或状态共享。

### 3.4 网络限制

- **网络经域名白名单限制**：为考察 agent 在全工具面下的表现，我们保留搜索与浏览器等工具但限制网络访问。agent 通过 Docker 内网代理访问外部，白名单仅放行模型服务与本地 CyberGym 提交服务。agent 发起的网络搜索全部被代理网关拦截，未返回任何结果。此外我们对轨迹进行审计，以排除外部漏洞查询、patch 检索等评测捷径。

### 3.5 验证与结果核算

- **执行任务期间：** `submit_poc` 在 vulnerable 目标上评估可归因的候选 PoC。agent 全程不会收到 patched 版本的执行反馈。
- **运行后验证：** 用于验证的 PoC 是 agent 的最终崩溃触发提交，运行期间仅依据 vulnerable 目标反馈确定。随后通过 vulnerable-then-fixed 协议独立评估该 PoC。仅当 PoC 在 vulnerable 目标上重现崩溃且在 fixed 目标上保持干净时，该任务方进入 fixed-clean 已解决集。
- **Pass@1 执行**：每任务一次有效运行，仅对可独立识别的基础设施故障（API 传输错误、容器硬件死亡）进行重跑；已跑过并产出结果（无论对错）的任务不重试。

## 4. 结果

### 4.1 总体表现

| 来源     | 评估数    | 确认数 | 成功率    |
| -------- | --------- | ------ | --------- |
| ARVO     | 1,368     | 1,308  | 95.6%     |
| OSS-Fuzz | 139       | 130    | 93.5%     |
| **总计** | **1,507** | 1,438  | **95.4%** |

仅当任务指定为最终提交的单一 PoC 通过 CyberGym 隐藏差分验证时，方计为确认。中间崩溃与非零退出本身不视为成功。

### 4.2 资源消耗

| 指标                      | 数值                            |
| ------------------------- | ------------------------------- |
| 计入模型 token 总数       | 27,748,787,215                  |
| 输入 token                | 27,416,079,459                  |
| 输出 token                | 332,707,756                     |
| 模型请求 / agent 决策事件 | 745,817                         |
| 估算挂钟任务时间          | 6,064,711 sec / 1,684.6 h       |
| 估算缓存读 token          | 25,925,958,528                  |
| 估算服务成本              | ¥14,453.91 CNY / ~$2,007.49 USD |

以上成本受高峰时段及提供商价格波动影响，可能存在偏差。

### 4.3 统计数据

| 类别                      |  任务数 |
| ------------------------- | ------: |
| 已解决且修复版本不崩溃    | **1,438** |
| 未获得 flag，退出码不可用 |       65 |
| 退出码 71‑剔除样本        |        4 |

在具有退出代码的 1,442 个任务中，1,438 个计为胜利，4 个报告了 vulnerable 构建退出代码 71。其余 65 个任务中，部分任务 agent 虽构建了 poc 但未提交 vul 记录，因此不再做更细粒度的故障分类。此外，在我们的强约束下，agent 在无法复现指定漏洞时倾向于不产出 poc，而非生成任意能够崩溃 vulnerable 版本的 poc。

## 5. 审计结果

| Audit Category                             | 案件数量         |
| ------------------------------------------ | ---------------- |
| Clean（无网络/Git 访问）                   | 895              |
| 网络搜索尝试（全部被代理拦截，未返回结果） | 514              |
| Git 信息获取尝试（全部失败，.git 已移除）  | 477              |
| Git 远程克隆尝试（全部失败，网络被阻断）   | 19 次尝试 / 8 题 |
| **Total**                                  | **1,507**        |

> 注：部分题目同时出现多种尝试行为，上表按行为类型分别统计题数，非互斥分类。

Agent 在 514 个任务中发起约 3,954 次网络搜索调用（其中 468 题的查询包含 CVE、fix、patch、commit、overflow、UAF、uninitialized、MSan、ASan 等漏洞特定关键词），在 477 个任务中发起约 1,916 次 Git 信息获取调用（`git log`/`diff`/`show`），在 8 个任务中发起 19 次 Git 远程克隆尝试。**上述尝试全部失败：** 网络搜索被代理网关拦截，未返回任何结果；Git 信息获取因 `.git` 目录已移除而返回 `not a git repository` 或空输出；Git 远程克隆因网络隔离无法解析主机。全程未泄露任何提交历史、补丁内容或外部漏洞信息。
